# lesson24: 使用性テスト — 3 つの評価技法とアクセシビリティでテストアナリストが貢献すること

## このレッスンで学ぶこと

- 使用性が、インタラクション容易性と便益性を含む広い概念であることを説明できるようになる
- 使用性テストが評価する 3 つの側面（インタラクション容易性・ユーザーエクスペリエンス・アクセシビリティ）を区別できるようになる
- 使用性レビュー・使用性テストセッション・ユーザーアンケートのそれぞれで、テストアナリストが何を貢献するかを説明できるようになる
- アクセシビリティテストの一般的なテスト目的と、求められる適合レベルの決め方を説明できるようになる

## 使用性という広い概念

**使用性**は、明示された利用状況において、明示されたゴールを達成するために、明示された利用者がコンポーネントやシステムを利用できる度合いです。シラバスはこの言葉を、ユーザーに関連する品質特性の広範な概念として使います。具体的には、次の 2 つを含みます。

| 含まれるもの | 出どころ |
|------|------|
| **インタラクション容易性** | ISO/IEC 25010（2023 年版）の製品品質モデル |
| 便益性 | ISO/IEC 25019（2023 年版）の利用時の品質モデル |

::: info 使用性からインタラクション容易性への名称変更
ISO/IEC 25010 の 2011 年版で「使用性」と呼ばれていた品質特性は、2023 年版で「インタラクション容易性」に名前が変わりました。それでもシラバスは、使用性テストのシラバス（ISTQB-UT）と整合させるために「使用性」の用語を使い続けています。試験でも「使用性テスト」の表記で問われます。
:::

使用性テストの詳細は、ISTQB の使用性テストシラバス（ISTQB-UT）、ISO 9241-210、UXQB の Foundation Level シラバスに委ねられています。AL-TA で問われるのは、テストアナリスト（TA）が使用性テストにどう貢献するかです。

## 使用性テストが評価する 3 つの側面

使用性テストは通常、次の 3 つの側面を中心に評価します。

| 側面 | 評価すること |
|------|------|
| インタラクション容易性 | ユーザーが、特定の使用コンテキストにおいて、効果的・効率的・満足にタスクを完了できるか |
| **ユーザーエクスペリエンス** | テスト対象とのやりとりの前・最中・後における、ユーザーの知覚 |
| **アクセシビリティ** | 障がいのあるユーザー、多様な文化的背景を持つユーザー、言語の障壁を持つユーザーが、効果的かつ効率的にシステムを利用できるか |

::: tip ユーザーエクスペリエンスは「最中」だけではない
ユーザーエクスペリエンスには、使う前の期待や、使い終えた後の印象も含まれます。アプリの説明を読んで抱いた期待と実際の操作感のずれも、ユーザーエクスペリエンスの評価対象です。「操作している間の使いやすさ」だけに絞った説明はひっかけになります。
:::

## テストアナリストが早い段階から協力できる理由

TA は、次のような知識を持っています。

- ターゲットユーザーグループと、そのゴール
- ユーザーの使用時のコンテキスト
- システムを使う際に起こりうる困難
- 否定的なユーザーエクスペリエンス

この知識を活用することで、TA は早い段階から使用性テストに協力できます。使用性の専門家が評価するとしても、「誰が、どんな状況で、何をしようとして使うのか」を具体的に語れる TA の知識は、評価の土台になります。

## 3 つの使用性評価技法とテストアナリストの貢献

シラバスは、主要な使用性評価技法を 3 つ挙げ、それぞれに TA がどう貢献できるかを示しています。

### 使用性レビュー

**使用性レビュー**は、使用性の専門家が行うレビューです。潜在的な使用性の問題や、確立された基準からの逸脱を識別します。形式は、非形式的レビューからインスペクションまでさまざまです。

TA の貢献は、レビュー基準を調整することです。一般的な使用性チェックリストをそのまま使うのではなく、次に合わせて調整します。

- ユーザーグループの特定のニーズ
- 特定のビジネス目標と優先度
- 使用コンテキスト

### 使用性テストセッション

**使用性テストセッション**では、将来のユーザーまたはその代表者が、あらかじめ定義されたタスクを実行します。これにより、タスクを効果的・効率的・満足に完了できるかを評価します。

TA の貢献は、セッションのシナリオ設計です。次のものに従ってシナリオを作ります。

| シナリオの根拠 | 内容 |
|------|------|
| ペルソナ | 典型的なユーザー像 |
| ユーザーグループ | 対象となるユーザーの集まり |
| 運用プロファイル | コンポーネントやシステムの実際または予測される利用パターン（[lesson09](/lessons/lesson09/)） |

参加者はあくまで将来のユーザーまたはその代表者です。TA の役割は、参加者が実際の利用に近い流れでタスクに取り組めるよう、シナリオを用意することにあります。

### ユーザーアンケートまたは調査

評価とフィードバックを含む**ユーザーアンケート**や調査は、ユーザーの満足度を計測します。シラバスが挙げる例は、SUMI（Software Usability Measurement Inventory）と WAMMI（Website Analysis and Measurement Inventory）です。

TA の貢献は、アンケートの設計と回答の評価の支援です。使用コンテキストにおける対象ユーザーの特定のゴールに対応するように、設問を設計し、回答を評価します。

### 3 つの技法の対応表

| 評価技法 | 誰が何をするか | TA の貢献 |
|------|------|------|
| 使用性レビュー | 使用性の専門家が、問題や基準からの逸脱を識別する | レビュー基準をユーザーグループ・ビジネス目標・使用コンテキストに合わせて調整する |
| 使用性テストセッション | 将来のユーザーまたはその代表者が、定義されたタスクを実行する | ペルソナ・ユーザーグループ・運用プロファイルに従ってシナリオを設計する |
| ユーザーアンケートまたは調査 | ユーザーが評価とフィードバックを回答し、満足度を計測する | 対象ユーザーのゴールに対応するよう、設計と回答の評価を支援する |

## アクセシビリティテストと標準への適合

アクセシビリティテストの一般的なテスト目的は、標準への適合を検証することです。

| 標準の種類 | 例 |
|------|------|
| 国際標準 | ウェブコンテンツのアクセシビリティガイドライン（WCAG） |
| 国ごとの標準 | 英国の平等法、米国の米国人障害者法 |

WCAG は、ウェブコンテンツのアクセシビリティの程度を示す 3 つの適合レベルを定義しています。A・AA・AAA の順に、求められる程度が高くなります。

TA の貢献は、使用コンテキストを分析することで、求められる適合レベルと、意図するターゲットグループの具体的なニーズを識別することです。どのレベルを目標にするかは、誰がどんな状況で使うかから決まります。

## 例題 テストアナリストの貢献として適切なものの判別

::: info 題材 自治体の窓口予約システム
住民が来庁の予約・変更・取り消しをするシステムを開発しています。利用者には、スマートフォンに慣れた若い住民、画面の拡大表示が必要な高齢の住民、日本語が母語でない住民が含まれます。外部の使用性の専門家が使用性レビューと使用性テストセッションを行う予定です。
:::

TA の貢献として挙がった候補を、シラバスの記述に照らして判別します。

| 候補 | 判別 | 理由 |
|------|------|------|
| 3 種類の住民のペルソナごとに、予約から変更までの代表的な利用の流れをシナリオとして用意する | 適切 | ペルソナや運用プロファイルに従ったシナリオ設計は、セッションへの TA の貢献そのもの |
| 専門家が持ち込んだ一般的なチェックリストに、予約の変更や取り消しが見つけやすいかという窓口予約に固有の項目を足す | 適切 | レビュー基準を使用コンテキストに合わせて調整している |
| 使用コンテキストを分析して、どの適合レベルを求めるかと、拡大表示や多言語などのニーズを整理する | 適切 | アクセシビリティテストでの TA の貢献 |
| 窓口業務に最も詳しい職員を参加者に選ぶ | 不適切 | ターゲットユーザーは住民であり、業務に詳しい職員ではユーザーグループの特性を反映できない |
| TA 自身が参加者としてセッションに入り、タスクをこなして効率を評価する | 不適切 | 参加者は将来のユーザーまたはその代表者であり、TA が代わりになることではない |
| セッション中に参加者が迷ったら、正しいボタンを教える | 不適切 | 評価したいのはユーザーが自力でタスクを完了できるかなので、手助けすると評価が成り立たない |

試験では、このように複数の活動を並べて「TA の最も適切な貢献はどれか」と問われます。「ユーザーの代わりをする」「ユーザーを導く」方向の選択肢は、貢献に見えて不適切です。

## 試験のポイント

- 3 つの評価技法と TA の貢献の対応（レビューは基準の調整、セッションはペルソナ・ユーザーグループ・運用プロファイルに基づくシナリオ設計、アンケートは設計と回答の評価の支援）が K2 の中心
- TA 自身が参加者になる、参加者を手助けする、業務に最も詳しい人だけを参加者に選ぶ、といった選択肢は貢献として不適切なひっかけ
- 使用性テストが評価する 3 つの側面（インタラクション容易性・ユーザーエクスペリエンス・アクセシビリティ）を区別し、ユーザーエクスペリエンスは「前・最中・後」の知覚を含む
- アクセシビリティテストの一般的な目的は標準への適合で、WCAG の適合レベルは A・AA・AAA の 3 段階、TA は使用コンテキストの分析から求められるレベルとニーズを識別する
