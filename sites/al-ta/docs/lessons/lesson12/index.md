# lesson12: ランダムテスト — 確率分布で入力を選ぶ技法の利点と制限

## このレッスンで学ぶこと

- ランダムテストが確率分布に基づいて入力データを選ぶ仕組みを説明できるようになる
- 妥当性確認と検証とで確率分布の選び方が変わる理由を説明できるようになる
- ガイドなしランダムテストとガイドありランダムテストを区別できるようになる
- カバレッジ基準がないことと終了基準の決め方の関係を説明できるようになる
- ランダムテストの利点と制限を要約できるようになる

## ランダムテストの仕組み

**ランダムテスト**は、テストアイテムの入力ドメインから、指定した確率分布に基づいてテストデータをランダムに選ぶ、データに基づくテスト技法です（データに基づくテスト技法の位置づけは [lesson10](/lessons/lesson10/)）。

「ランダムに選ぶ」といっても、どの値がどのくらいの確率で選ばれるかは**確率分布**で指定し、その分布に従って値を引きます。どの値も同じ確率で選ぶのは、分布として一様分布を指定した場合にあたります。シラバスが扱うのはランダムな入力データによるテストだけで、ランダムなイベントによるテストは含みません。

### 確率分布の選び方

確率分布は、テストの目的によって選び方が変わります。

| 目的 | 使う確率分布 | 理由 |
|---|---|---|
| 妥当性確認 | 運用プロファイルに基づく分布 | 実際の使われ方に近い入力で、ユーザーのニーズに合うかを見るため |
| 検証 | 利用状況に依存しない分布 | 利用頻度の偏りによるバイアスを避け、仕様どおりかを広く見るため |

**運用プロファイル**は、コンポーネントやシステムの実際の利用パターン、または予測される利用パターンです。よく使われる入力ほど多く選ばれるので、妥当性確認に向きます。一方、検証ではめったに使われない入力も同じように確かめたいので、利用状況に依存しない分布にします。

### 期待結果とテストオラクル

入力をランダムに作ると、期待結果も入力ごとに用意しなければなりません。テストオラクルを使って期待結果をテストケースに追加することがあり、入力の数が多いため、多くの場合は自動化したテストオラクルが必要です。テストオラクルの決め方は [lesson05](/lessons/lesson05/) で扱います。

## ガイドなしとガイドあり

ランダムテストは、確率分布をテストの途中で変えるかどうかで 2 つに分かれます。

| 種類 | 確率分布 | ねらい |
|---|---|---|
| ガイドなしランダムテスト | プロセス全体を通して一定 | 指定した分布のとおりに入力を引き続ける |
| ガイドありランダムテスト | これまでに選んだ値に基づいて調整し、時間とともに変化させる | 欠陥がドメインの特定の領域に集中しやすいことを踏まえ、入力ドメインを効果的にカバーする |

ガイドありランダムテストの代表が**適応的ランダムテスト**です。すでに選んだ値の近くは選ばれにくくし、まだ試していない領域から値を引くように分布を調整します。同じような値ばかり引いてしまう冗長さを抑えられるのが、ガイドなしとの違いです。

## カバレッジ基準と終了基準

ランダムテストには、広く合意されたカバレッジ基準がありません。ドメインテストや組み合わせテストのように「カバレッジアイテムをすべて含んだら終わり」とは言えないので、終了基準は次のような完了度の尺度に頼ることになります。

- 実行したテストの数
- テストに使った時間
- それらと同様の、完了度を示す尺度

## 利点と制限

### 利点

| 利点 | 内容 |
|---|---|
| ドメイン知識が限られていても使える | 仕様の細部を知らなくても、入力ドメインと確率分布があればテストデータを作れる |
| 大量のテストデータを用意できる | 手作業では作れない量の入力を生成できる |
| コスト効率が高い | テストデータの設計に人手をかけずに済む |
| 信頼性の示唆が得られる | 確率的な観点から、テスト対象の信頼性について示唆が得られる |
| バイアスを避けられる | 特定のコードや機能を信頼しすぎて手動テストで欠陥を見落とす、といった偏りを避けられる |

### 制限

| 制限 | 内容 |
|---|---|
| データセマンティクスの軽視 | 値の意味を考えずに選ぶ |
| データの意味に関わる欠陥の見逃し | 意味のある値の組み合わせに依存する欠陥を見逃す可能性がある |
| 特定の欠陥の見落とし | 境界のような狙いどころを意図して選ばないため、特定の欠陥を見落とす |
| 冗長なテストの生成 | 同じような入力を何度も引く |
| 自動化したテストオラクルへの依存 | 大量の入力に対する期待結果を人手では用意できない |
| テスト結果の不整合 | ランダムな出力により、実行のたびに結果が変わることがある |

利点と制限のどちらが大きいかはコンテキストによるので、テストのコンテキストごとに両者のバランスを取ります。

### 有効性の見直し

ランダムテストは、従来は他のテスト技法より効果が低いと考えられてきました。近年の多くの実証研究では、ドメイン知識が限られている場合や大量のテストデータが必要な場合には、他のデータに基づくテスト技法より効果的かつ効率的になり得ることが示されています。

### ファズテストとカオスエンジニアリングへの応用

ランダムテストは、ファズテストやカオスエンジニアリングにも応用されています。

- **ファズテスト**は、大量のランダムなデータを使ってテストの入力データを生成するテスト技法で、不正な入力に対する堅牢性やセキュリティの弱点を探す
- **カオスエンジニアリング**は、サーバーの停止や通信の遅延といった障害を意図的に起こし、システムがそれに耐えられるかを確かめる取り組みで、どの障害をいつ起こすかにランダム性を使う

## 試験のポイント

- 妥当性確認には運用プロファイルに基づく分布、検証には利用状況に依存しない分布を使う（対応を逆にした選択肢に注意）
- ガイドありランダムテストは、これまでに選んだ値に基づいて分布を変化させて特定の領域への欠陥の集中に対応するが、カバレッジ基準がないことやテストオラクルへの依存はガイドの有無では変わらない
- 利点 5 つと制限 6 つを漏れなく要約できるようにする（K2）
