# lesson16: デシジョンテーブルテスト — 最小化とチェックサムでルールの抜け漏れを見つける

## このレッスンで学ぶこと

- ルールに基づくテスト技法の 2 つと、それが検証する振る舞いの特徴を説明できるようになる
- 完全なデシジョンテーブルのルール数を求め、don't care 演算子「-」でルールをマージして最小化できるようになる
- 一貫性・実現可能性・完全性・正確性の 4 つのレビュー基準と、ルールが重複しないことの意味を説明できるようになる
- 最小化したデシジョンテーブルのチェックサムを計算し、重複やギャップを見つけられるようになる
- デシジョンテーブルのカバレッジの測り方と、リスクレベルが高いときに最小化を控える理由を説明できるようになる

## ルールに基づくテスト技法の位置づけ

ビジネスルールのように、テストアイテムの状態に関係なく常に成り立つルールで仕様化された振る舞いがあります。シラバスは、こうした状態を持たない振る舞いの実装を検証する技法を**ルールに基づくテスト技法**と呼び、2 つの技法を取り上げています。

| 技法 | テスト条件 | レッスン |
|------|------|------|
| デシジョンテーブルテスト | 条件の組み合わせと、それに対応するアクション | このレッスン |
| メタモルフィックテスト | テストケースの入力の変化と期待結果の関係 | [lesson17](/lessons/lesson17/) |

状態に依存する振る舞いを扱う振る舞いに基づくテスト技法（[lesson14](/lessons/lesson14/)）との対比で押さえておくと、技法の選択（[lesson21](/lessons/lesson21/)）で迷いません。

デシジョンテーブルの基本（条件とアクションを行に、ルールを列にする構造、T／F と「-」の表記、完全な表と簡略化・最小化の関係）は FL シラバス 4.2.3 で学んだとおりです。このレッスンでは、その先の最小化の手順、レビュー基準、チェックサムを扱います。シラバスの用語と表記は OMG の DMN 標準に準拠しています。

## 完全なデシジョンテーブルと最小化

テストアナリストは通常、完全なデシジョンテーブルを作るか、テストベースにある既存のデシジョンテーブルを分析するところから始めます。

**完全なデシジョンテーブル**のルール数は、各条件の値の数の積です。条件がすべて真偽の 2 値なら、条件 n 個で 2 の n 乗になります。条件の数と値の数が増えるとルール数は指数関数的に増えるため、表を**最小化**する動機になります。最小化とは、元のデシジョンテーブルから、ルール数がより少ない等価なデシジョンテーブルを導くことです。元の表は完全な表でなくてもかまいません。

### don't care 演算子によるマージ

最小化では、**don't care 演算子**の「-」を使ってルールをマージします。

実行不可能なルール、つまり絶対に起こらない条件値の組み合わせを持つルールは、マージのときに無視することが推奨されています。多くの場合、マージの前に表から削除します。

::: info 実行不可能なルールの例
条件に「会員である」と「会員ランクがゴールドである」の 2 つがあるとき、「会員でない」かつ「ゴールドである」組み合わせは起こりえません。この組み合わせを含むルールは、マージの前に削除します。
:::

### 体系的な最小化の手順

シラバスが挙げる体系的な最小化アルゴリズムは、次の条件を満たすルールの組を探してマージするものです。

- アクションが等価である
- 1 つの条件だけが異なる
- その条件の取りうる値をすべてカバーしている

見つけたらマージし、異なっていた条件の値を「-」に置き換えます。これを繰り返します。

ただし、体系的な最小化の結果は、どの列（条件）から最小化するかの順序に依存することがあり、常に最適な結果になるとは限りません。テストアナリストは、結果の表にさらなる最小化の余地がないかを確認しなければなりません。

経費申請の処理ルールを題材に、完全なデシジョンテーブルを最小化して列数を求めます。

- 領収書があり、金額が 1 万円を超える場合、事前申請があれば自動承認する
- 領収書があり、金額が 1 万円を超え、事前申請がない場合、申請者が管理職なら上長の承認へ回し、管理職でなければ差し戻す

## 例題 1 の手順

条件 C4、C3、C1、C2 の順にマージを試みます。各段階で「アクションが等価で、その条件だけが異なり、T と F の両方がそろっている組」を探します。

### C4 でのマージ

C4 だけが異なる組は、隣り合う列どうしです。

| 組 | アクション | 結果 |
|------|------|------|
| R1、R2 | どちらも A1 | マージして T T T - |
| R3、R4 | どちらも A1 | マージして T T F - |
| R5、R6 | どちらも A3 | マージして T F T - |
| R7、R8 | どちらも A3 | マージして T F F - |
| R9、R10 | A1 と A2 | マージしない |
| R11、R12 | A1 と A3 | マージしない |
| R13、R14 | どちらも A3 | マージして F F T - |
| R15、R16 | どちらも A3 | マージして F F F - |

16 列が 10 列になりました。

### C3 でのマージ

今度は、C3 だけが異なる組を探します。「-」になった条件は、同じ「-」どうしであれば一致しているとみなします。

| 組 | アクション | 結果 |
|------|------|------|
| T T T -、T T F - | どちらも A1 | マージして T T - - |
| T F T -、T F F - | どちらも A3 | マージして T F - - |
| R9、R11（F T T T、F T F T） | どちらも A1 | マージして F T - T |
| R10、R12（F T T F、F T F F） | A2 と A3 | マージしない |
| F F T -、F F F - | どちらも A3 | マージして F F - - |

10 列が 6 列になりました。

### C1 でのマージ

C1 だけが異なる組を探します。

| 組 | アクション | 結果 |
|------|------|------|
| T F - -、F F - - | どちらも A3 | マージして - F - - |
| T T - -、F T - T | どちらも A1 だが C1 と C4 の 2 つが異なる | マージしない |

6 列が 5 列になりました。C2 だけが異なる組はないので、ここで止まります。

### 最小化の結果

| | M1 | M2 | M3 | M4 | M5 |
|---|---|---|---|---|---|
| C1 | T | - | F | F | F |
| C2 | T | F | T | T | T |
| C3 | - | - | - | T | F |
| C4 | - | - | T | F | F |
| A1 | X | | X | | |
| A2 | | | | X | |
| A3 | | X | | | X |

最小化後の列数は 5 です。最後に、さらなる最小化の余地を確認します。アクションが等価な M1 と M3 は 2 つの条件が異なり、M2 と M5 は M2 側の「-」が M5 では個別の値になっているため、どちらもマージできません。

::: tip 順序によって結果が変わる
C1 から先にマージすると、A1 の列は「- T - T」と「T T - F」の 2 列になります。この例では列数は同じ 5 ですが、表の形は違います。順序によっては列数まで変わることがあるので、最小化を終えたら必ず「まだマージできる組がないか」を確認します。
:::

## デシジョンテーブルのレビュー基準

デシジョンテーブルを、必要なら他のステークホルダーと一緒にレビューするのもテストアナリストの仕事です。レビューの基準は 4 つです。

| 基準 | 確認すること |
|------|------|
| **一貫性** | 2 つの異なるルールが同じ条件値の組み合わせに適用されるなら、そのアクションが等価である |
| **実現可能性** | 実現不可能なルールを含まない |
| **完全性** | 実現可能な条件値の組み合わせが欠けていない |
| **正確性** | ルールがシステムの意図した振る舞いをモデル化している |

これに加えて、ルールは**重複しない**ことが望まれます。どの条件値の組み合わせにも、適用されるルールが最大で 1 つという状態です。重複は、元のデシジョンテーブルがすでに最小化されている場合や、ルールのマージが正しくない場合に起こります。

一貫性と重複の違いに注意します。2 つのルールが同じ組み合わせに当てはまっても、アクションが同じなら一貫性は保たれています（重複はしている）。アクションが違えば一貫性の違反です。

## チェックサムによる重複とギャップの検出

**チェックサムプロシジャー**は、最小化したデシジョンテーブルの各ルールが元の表の何個分のルールを表しているかを使って、重複とギャップを見つける手順です。

ルールのスコアは次のように計算します。

- 条件に「-」がないルール（すべての条件に個別の値があるルール）のスコアは 1
- 「-」が 1 つあるごとに、その条件の個別の値の数をスコアに乗じる

ルールのスコアの合計が、最小化したデシジョンテーブルのチェックサムです。元のデシジョンテーブルのチェックサム（完全な表なら、そのルール数）と比べて判断します。

| 比較の結果 | 意味 |
|------|------|
| 元の表より小さい | 最小化した表は不完全である（ギャップがある） |
| 元の表より大きい | いくつかのルールが重複しているか、余分なルール（実行不可能な組み合わせなど）がある |
| 等しい | 最小化が正しく行われていれば等しくなる |

ただし、チェックサムが等しいだけでは、最小化した表が元の表と等価であることは保証されません。

## 例題 2 の題材

購入時のポイント付与ルールを最小化したデシジョンテーブルが、レビューに回ってきました。チェックサムを計算し、重複や矛盾を見つけます。

| 記号 | 内容 |
|------|------|
| C1 | 会員である |
| C2 | 購入額が 5,000 円以上である |
| C3 | キャンペーン期間中である |
| A1 | 通常ポイントを付与する |
| A2 | ボーナスポイントを付与する |
| A3 | ポイントを付与しない |

| | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| C1 | F | T | T | T |
| C2 | - | - | T | F |
| C3 | - | T | - | - |
| A1 | | X | X | X |
| A2 | | X | X | |
| A3 | X | | | |

条件は 3 つともブール値なので、完全な表のチェックサムは 2 の 3 乗で 8 です。

## 例題 2 の手順

まず、各ルールのスコアを計算します。

| ルール | 「-」の数 | スコア |
|------|------|------|
| R1 | 2 | 2 × 2 で 4 |
| R2 | 1 | 2 |
| R3 | 1 | 2 |
| R4 | 1 | 2 |

チェックサムは 4 足す 2 足す 2 足す 2 で 10 です。元の表の 8 より大きいので、重複か余分なルールがあります。

次に、各ルールが表す組み合わせを展開して、どこが重なっているかを特定します。組み合わせは C1、C2、C3 の順に書きます。

| ルール | 表す組み合わせ |
|------|------|
| R1 | F F F、F F T、F T F、F T T |
| R2 | T T T、T F T |
| R3 | T T T、T T F |
| R4 | T F T、T F F |

| 組み合わせ | 適用されるルール | 判定 |
|------|------|------|
| T T T | R2、R3 | 重複している。アクションはどちらも A1 と A2 なので一貫性はある |
| T F T | R2、R4 | 重複している。R2 は A1 と A2、R4 は A1 だけなので一貫性に違反している |
| その他の 6 通り | 1 つずつ | 問題なし |

8 通りの組み合わせがすべて少なくとも 1 つのルールに含まれているので、ギャップはありません。チェックサムが 8 より 2 大きかった理由は、2 つの組み合わせが二重に数えられていたからです。

最後に、意図した振る舞いを確認して直します。このルールの意図は「キャンペーン期間中の会員にはボーナスポイントも付与する」なので、R2 を正としてキャンペーン期間外に限定するよう R3 と R4 の C3 を F に変えます。

| | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| C1 | F | T | T | T |
| C2 | - | - | T | F |
| C3 | - | T | F | F |
| A1 | | X | X | X |
| A2 | | X | X | |
| A3 | X | | | |

修正後のチェックサムは 4 足す 2 足す 1 足す 1 で 8 になり、元の表と等しくなりました。

::: warning チェックサムが等しくても安心できない
修正前の表で、R1 が「F - T」（C3 が T）だったとします。スコアは 2 足す 2 足す 2 足す 2 で 8 となり元の表と等しくなりますが、F F F と F T F の 2 通りがどのルールにも含まれず、T T T と T F T の 2 通りが重複しています。ギャップと重複が打ち消し合っているだけです。チェックサムは「違っていれば必ず問題がある」とは言えますが、「等しければ等価である」とは言えません。
:::

## カバレッジの測定と最小化を控える判断

デシジョンテーブルのカバレッジは、実行した列の数を、デシジョンテーブルの実行可能な列の総数で割って測定します。例題 1 の最小化した表なら、5 列のうち 4 列を実行した時点で 4 ÷ 5 で 80% です。

ルールからテストケースを実装するときは、条件とアクションの両方を実装します。「-」は少なくとも 2 つの値を表すので、そのルールの「-」をどの値で実装するかはテストアナリストが決めます。

ただし、そのデシジョンテーブルに関連するリスクレベルが高い場合、テストアナリストは最小化を控えるべきです。「-」を 1 つの値で代表させず、完全なデシジョンテーブルの実行可能な列を基準にカバレッジを測定します。例題 1 なら、分母は 5 ではなく 16 になります。

## 試験のポイント

- K3 で問われるのは最小化後の列数とルールのスコアの計算で、マージは「アクションが等価で 1 つの条件だけが異なり、その値をすべてカバーする組」を順に探し、スコアは「-」1 つにつきその条件の値の数を乗じる
- チェックサムは元の表より小さければ不完全、大きければ重複か余分なルール、等しくても等価の保証にはならない
- 一貫性（同じ組み合わせに当てはまるルールはアクションが等価）と重複しないこと（当てはまるルールは最大 1 つ）を区別し、レビュー基準 4 つ（一貫性・実現可能性・完全性・正確性）を想起できるようにする
- カバレッジの分母は実行可能な列の総数で、リスクレベルが高ければ最小化を控えて完全な表の実行可能な列で測る
