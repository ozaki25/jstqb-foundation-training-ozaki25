# lesson07: テストウェアをマネジメントするツール — 5種類のツールと TA の支援

## このレッスンで学ぶこと

- ツールを使ったテストウェアのマネジメントがテストプロセスにもたらす価値を説明できるようになる
- テストウェアをマネジメントする5種類のツールと、それぞれが扱う対象を要約できるようになる
- テストアナリストがテストウェアのマネジメントを支援する6つのやり方を要約できるようになる
- 場面の説明から、どのツールの守備範囲かを見分けられるようになる

## ツールでテストウェアをマネジメントする価値

**テストウェア**は、テスト条件・テストケース・テストスクリプト・テストデータ・テスト結果など、テストプロセスで生み出される作業成果物の総称です。テストアナリスト（TA）は、自分が責任を負うテストウェアの品質を確実にしなければなりません。テストウェアが増えてくると、何がどのバージョンに対応し、どれが最新で、どのテストがどの要件を検証しているかを手作業で追い続けるのは無理があります。

ツールで適切にテストウェアをマネジメントすると、TA はテストプロセス全体を次のように支えられます。

| ツールがもたらすもの | TA にとっての意味 |
|------|------|
| 作業成果物のステータス | どのテストケースが作成済みか、実行済みか、合格か不合格かが見える |
| テストモニタリングとテストコントロールの支援 | 進捗や品質の状況を根拠をもって報告し、必要な対応を判断できる |
| 過去のテストランの記録 | テスト対象に故障が起きたとき、過去のテストランの結果を確認し、欠陥が発生した時点を分析できる |

## テストウェアをマネジメントする5種類のツール

シラバスが挙げる主要なツールは次の5種類です。

| ツール | 扱う対象 | 主な機能 |
|------|------|------|
| **テストマネジメントツール** | 関連するすべてのテストウェア（テスト条件、テストケース、テストスクリプト、テストスイート、テストラン） | リポジトリの提供、トレーサビリティ（トレーサビリティマトリクスなど）、テストケースの検索、テストランのスケジュール、テスト結果の記録、テスト進捗と品質の全体的なレポート |
| **欠陥マネジメントツール** | 欠陥 | 欠陥解決のプロセスの記録、優先順位付け、モニタリング |
| **テストデータマネジメントツール** | テストデータ | テストデータの作成と保守。機密データの保護を含む（[lesson04](/lessons/lesson04/)） |
| **構成管理ツール** | 開発・リリース・運用プロセスにおけるテスト関連の活動 | テスト環境の構成や可用性のマネジメントなど |
| **要件マネジメントツール** | ハイレベルの要件 | 要件の格納と追跡。SDLC 全体を通じて要件が明確に定義され、バージョンが付けられ、追跡されることを確かにする |

::: tip 守備範囲の見分け方
試験では、作業の内容からどのツールの機能かを選ばせる問題が想定されます。「テストケースをどう整理し、どの結果を記録するか」ならテストマネジメントツールです。「欠陥の記録から解決まで」は欠陥マネジメントツール、「個人情報を仮名化したデータの用意」はテストデータマネジメントツールが受け持ちます。「テスト環境の構成の管理」は構成管理ツール、「要件のバージョン管理」は要件マネジメントツールです。
:::

## TA がテストウェアのマネジメントを支援する6つのやり方

ツールを入れただけではテストウェアは整いません。TA は次の6つのやり方でテストウェアのマネジメントを支援します。

| やり方 | 具体例 |
|------|------|
| プロジェクトとリリースを分析し、テストウェアの適切なサブセットを選択する | テスト対象（SUT）のバージョンに合わせて、バージョンで識別される仕様を選ぶ |
| テストケースを整理するための構造を定義する | 機能別やモジュール別などの機能的構造、テストタイプ別や環境別などの技術的構造をテストマネジメントツール上に決める |
| テストケースにメタデータを追加する | テスト実行に関わる工数の情報、必要となる特定のテスト環境の情報 |
| トレーサビリティを確保する | 要件、テスト条件、テストケース、テストラン、欠陥の間をたどれるようにする |
| リグレッションテストのための正しいテストスイートを選択する | 手動実行用、自動実行用のそれぞれについて選ぶ（選び方は [lesson09](/lessons/lesson09/)） |
| テストケースの構成管理を行う | 古くなったテストケースの識別を含む |

6つを並べると、TA の支援は「選択する」「構造化する」「保守する」「トレーサビリティを確保する」「バージョンをコントロールする」の5つの動きにまとまります。ツールがテストプロセスを整理し、追跡し、品質を確保するのに役立つ一方で、効率的なテストとテストコントロールのためにこの5つの動きを担うのが TA です。

::: info インクリメンタル・イテレーティブ開発での重み
リリースのたびにテスト対象が変わる開発モデルでは、リリースごとに正しいテストケースのサブセットを選び直し、古くなったテストケースを見分ける作業が欠かせません。「テストウェアの適切なサブセットの選択」と「リグレッションテストのためのテストスイートの選択」は、こうした開発モデルでとくに効いてきます。
:::

## 試験のポイント

- 5種類のツール（テストマネジメント・欠陥マネジメント・テストデータマネジメント・構成管理・要件マネジメント）を扱う対象で見分けられるようにする（K2）
- TA の支援6つ（サブセットの選択・構造の定義・メタデータの追加・トレーサビリティの確保・リグレッションテストスイートの選択・テストケースの構成管理）を漏れなく想起できるようにする
- テストマネジメントツールが扱うのはテストウェアの整理と結果の記録であり、欠陥の重要度分類やテストデータの仮名化、テスト環境の構成管理は別のツールの守備範囲というひっかけに注意する
