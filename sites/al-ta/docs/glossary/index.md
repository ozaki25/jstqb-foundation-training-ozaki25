# 用語集

JSTQB Advanced Level テストアナリストのシラバス（V4.0）で、各章の冒頭に挙がっているキーワード 67 個を章別に整理するページです。各用語の説明と、その用語を主に説明しているレッスンへのリンクを載せます。

試験に K1（記憶）の出題はありませんが、キーワードの名前と定義を知っていることは K2 以上の問題を解く前提になります。定義は ISTQB 用語集（v4.8.1）に沿って、この教材の言葉で書き直しています。

::: tip 使い方
用語の表記はシラバス（V4.0.J01）に合わせています。ISTQB 用語集の日本語版と表記が異なる用語は、別表記を併記します。説明の最後にあるリンクは、主に説明しているレッスンを先に並べています。より詳しい説明や具体例はリンク先のレッスンで確認し、正確な定義は公式シラバスおよび ISTQB 用語集を参照してください。
:::

## 第1章 テストプロセスにおけるテストアナリストのタスク

### テストアナリストと開発ライフサイクル

| 用語 | 説明 |
|------|------|
| テストアナリスト（test analyst） | テスト分析・テスト設計・テスト実装・テスト実行に責任を持ち、ソフトウェアの非技術的な側面（ビジネス側面）に重点を置く人。技術的な側面はテクニカルテストアナリストが担う（[lesson01](/lessons/lesson01/)） |
| ソフトウェア開発ライフサイクル（software development lifecycle、SDLC） | ソフトウェア開発の各段階で行う活動と、それらの活動の論理的・時系列的な関連を表したもの。シーケンシャル・インクリメンタル・イテレーティブのどのモデルかで、テストアナリストの関わり方が変わる（[lesson01](/lessons/lesson01/)） |

### テストプロセスの活動

| 用語 | 説明 |
|------|------|
| テスト分析（test analysis） | テストベースを分析してテスト条件を識別する活動。「何をテストするか」を決める（[lesson02](/lessons/lesson02/)） |
| テスト設計（test design） | テスト条件からテストケースを導出し、明確にする活動。「どのようにテストするか」を記述する（[lesson02](/lessons/lesson02/)） |
| テスト実装（test implementation） | テスト実行に必要なテストウェアを準備する活動。テストプロシジャーの定義やテストデータの作成を含む（[lesson02](/lessons/lesson02/)） |
| テスト実行（test execution） | コンポーネントやシステムでテストを走らせ、実際の結果を得る活動。見つかった不正（シラバス 3.4.1 の表記では「異常」。英語はどちらも anomaly）の分析を含む（[lesson02](/lessons/lesson02/)） |

### テスト条件とテストケース

| 用語 | 説明 |
|------|------|
| テスト条件（test condition） | テスト対象のコンポーネントやシステムのうち、テストの対象にしようと決めた、テスト可能な側面（[lesson02](/lessons/lesson02/)） |
| テストケース（test case） | テスト条件に基づいて作る、実行の事前条件・入力値・アクション（該当する場合）・期待結果・実行の事後条件のセット（[lesson03](/lessons/lesson03/)、[lesson02](/lessons/lesson02/)） |
| ハイレベルテストケース（high-level test case） | 事前条件・入力データ・期待結果・事後条件（必要ならアクションも）を抽象的なレベルで書いたテストケース。論理的テストケース、抽象的テストケースとも呼ぶ（[lesson03](/lessons/lesson03/)） |
| ローレベルテストケース（low-level test case） | 事前条件・入力データ・期待結果・事後条件（必要ならアクションも）を具体的な値で書いたテストケース。具体的テストケース、物理的テストケースとも呼ぶ（[lesson03](/lessons/lesson03/)） |
| テストオラクル（test oracle） | 期待結果を判定するための情報源。テストベースや人の知識のほか、自動化したテストオラクルもある。オラクルとも呼ぶ（[lesson05](/lessons/lesson05/)） |

### テストウェア・テストデータ・テスト環境

| 用語 | 説明 |
|------|------|
| テストウェア（testware） | テストプロセスで作られる作業成果物。テストの計画・設計・実行・評価・報告に使う。テスト条件、テストケース、テストスクリプト、テストデータ、テスト結果などが含まれる（[lesson07](/lessons/lesson07/)、[lesson02](/lessons/lesson02/)） |
| テストスクリプト（test script） | テストを実行するための、順序付けられた一連の操作指示。キーワード駆動テストではキーワードを並べて書く（[lesson06](/lessons/lesson06/)、[lesson02](/lessons/lesson02/)） |
| テストデータ（test data） | テスト実行に必要なデータ。個人情報を含むデータの保護では、識別子を人工的なデータに置き換える可逆的な処理（仮名化）と、個人を特定できないようにデータを削除または変更する不可逆的な処理（匿名化）を区別する（[lesson04](/lessons/lesson04/)） |
| テスト環境（test environment） | テストの実行に必要な、ハードウェア・インスツルメンテーション・シミュレーター・ソフトウェアツール・その他の支援要素を含む環境。テストベッド、テストリグとも呼ぶ（[lesson04](/lessons/lesson04/)） |

### キーワード駆動テスト

| 用語 | 説明 |
|------|------|
| キーワード（keyword） | テスト実行中に行う特定のアクションを表す語句。アクションと検証に分類でき、ドメイン層とテストインターフェース層という少なくとも 2 つの抽象化レイヤーに存在する（[lesson06](/lessons/lesson06/)） |
| キーワード駆動テスト（keyword-driven testing） | テストスクリプトにキーワードを含め、そのキーワードを実装するスクリプトを補助ファイルに持たせるテスト自動化のアプローチ。手動テストにも使える（[lesson06](/lessons/lesson06/)） |

## 第2章 リスクベースドテストにおけるテストアナリストのタスク

### リスクとリスク分析

| 用語 | 説明 |
|------|------|
| プロダクトリスク（product risk） | プロダクトの品質に影響を与えるリスク。テストアナリストは影響のある品質特性で分類し、テストアイテムごとに評価する（[lesson08](/lessons/lesson08/)） |
| リスクベースドテスト（risk-based testing） | テスト活動とリソースのマネジメント・選択・優先順位付け・利用を、対応するリスクタイプとリスクレベルに基づいて行うテストアプローチ。リスク分析・リスクコントロール・定期的なリスクモニタリングで構成する（[lesson08](/lessons/lesson08/)） |
| リスク分析（risk analysis） | リスク識別とリスクアセスメントを行うプロセス。テストアナリストは、システムに関する知識と、どこで何が起きやすいかという経験的な知識を持ち込んで貢献する（[lesson08](/lessons/lesson08/)） |
| リスク識別（risk identification） | リスクを発見し、認識し、記述するプロセス。ふりかえり、リスクワークショップ、ブレーンストーミング、チェックリストの作成、ステークホルダーへのインタビューなどで行う（[lesson08](/lessons/lesson08/)） |
| リスクアセスメント（risk assessment） | 識別したリスクを検証し、リスクレベルを決定するプロセス。テストアナリストはリスクレベルを決める要素の見積もり、品質特性による分類、テストアイテムへの分解、軽減策の提案で貢献する（[lesson08](/lessons/lesson08/)） |

### リスクコントロールとリグレッションテスト

| 用語 | 説明 |
|------|------|
| リスクコントロール（risk control） | リスク軽減とリスクモニタリングからなる一連のプロセス。テストアナリストは、リグレッションテストの範囲の決定などでこれを実装する（[lesson09](/lessons/lesson09/)、[lesson08](/lessons/lesson08/)） |
| リスク軽減（risk mitigation） | リスクを特定のレベルまで減らす（またはそのレベルを維持する）ために、判断を下し、対策を実施するプロセス。レビューの実施、テスト技法とカバレッジレベルの適用、テストタイプの適用、リグレッションテストの実行などが含まれる（[lesson09](/lessons/lesson09/)） |
| リスクモニタリング（risk monitoring） | 既知のリスクの状況を確認し、ステークホルダーに報告する活動。リスクは時間とともに変わるので定期的に行い、テストアナリストはリスクレジスターの更新と軽減アクションの調整で貢献する（[lesson08](/lessons/lesson08/)） |
| リグレッションテスト（regression testing） | ソフトウェアの変更していない領域に欠陥が混入または露呈していないかを検出する、変更関連のテスト。時間・予算・環境の制約から、実行する範囲を選択することが多い（[lesson09](/lessons/lesson09/)） |
| 影響度分析（impact analysis） | 変更が影響するすべての作業成果物を識別すること。変更の実現に必要なリソースの見積もりを含む。自動テストを選ぶときに最も信頼できる、リグレッションテストの選択技法（[lesson09](/lessons/lesson09/)） |

## 第3章 テスト分析とテスト設計

### テスト技法の分類

| 用語 | 説明 |
|------|------|
| データに基づくテスト技法（data-based test technique） | テスト対象のデータをモデル化し、その要素をテスト条件とするテスト技法。ドメインテスト・組み合わせテスト・ランダムテストが該当する（[lesson10](/lessons/lesson10/)） |
| 振る舞いに基づくテスト技法（behavior-based test technique） | テスト対象の状態に依存する振る舞いをモデル化し、その要素をテスト条件とするブラックボックステスト技法。CRUD テスト・状態遷移テスト・シナリオベースドテストが該当する（[lesson13](/lessons/lesson13/)、[lesson14](/lessons/lesson14/)） |
| ルールに基づくテスト技法（rule-based test technique） | テスト対象の状態に依存しない振る舞いのルールをモデル化し、その要素をテスト条件とするブラックボックステスト技法。デシジョンテーブルテスト・メタモルフィックテストが該当する（[lesson16](/lessons/lesson16/)） |

### データに基づくテスト技法

| 用語 | 説明 |
|------|------|
| 同値パーティション（equivalence partition） | 仕様に基づいて、コンポーネントやシステムが同じように扱うと期待される値の領域の部分集合。ドメインテストでは、不可分条件をブール演算子でつないだ式で定義する（[lesson10](/lessons/lesson10/)） |
| ドメインテスト（domain testing） | 入力値のドメインにある複数の同値パーティションについて、境界の上・近傍・内側・外側の点（ON・OFF・IN・OUT ポイント）をテスト条件とするブラックボックステスト技法（[lesson10](/lessons/lesson10/)） |
| 組み合わせテスト（combinatorial testing） | 複数のパラメーターの値の特定の組み合わせをテスト条件とするブラックボックステスト技法。相互作用の故障を狙い、ベースチョイスカバレッジやペアワイズカバレッジを使う（[lesson11](/lessons/lesson11/)） |
| ランダムテスト（random testing） | 入力値をランダムに生成するブラックボックステスト技法。指定した確率分布に従って入力ドメインから値を選ぶ（[lesson12](/lessons/lesson12/)） |

### 振る舞いに基づくテスト技法

| 用語 | 説明 |
|------|------|
| CRUDテスト（CRUD testing） | エンティティに対する作成・読み込み・更新・削除の各操作をテスト条件とするブラックボックステスト技法。R の訳はシラバスでは「読み込み」、ISTQB 用語集の日本語版では「参照」（[lesson13](/lessons/lesson13/)） |
| 状態遷移テスト（state transition testing） | 状態遷移モデルの要素を実行するようにテストケースを設計するブラックボックステスト技法。Advanced Level では N スイッチカバレッジとラウンドトリップカバレッジが加わる。モデル化の過程で、到達不可能な状態や非決定的な動作といった仕様の欠陥も見つかる（[lesson14](/lessons/lesson14/)、[lesson27](/lessons/lesson27/)） |
| シナリオベースドテスト（scenario-based testing） | 外部アクターとテストアイテムの間の一連の相互作用をテスト条件とするブラックボックステスト技法。シナリオモデルにはユースケースとアクティビティ図を使う（[lesson15](/lessons/lesson15/)） |

### ルールに基づくテスト技法

| 用語 | 説明 |
|------|------|
| デシジョンテーブルテスト（decision table testing） | デシジョンテーブルに示された条件の組み合わせと、それに対応する結果（アクション）をテスト条件とするブラックボックステスト技法。Advanced Level では最小化とチェックサムを扱う（[lesson16](/lessons/lesson16/)） |
| メタモルフィック関係（metamorphic relation、MR） | テストアイテムに要求される振る舞いに基づいて、テストケースの入力の変化が期待結果にどう影響するかを記述したもの（[lesson17](/lessons/lesson17/)） |
| メタモルフィックテスト（metamorphic testing、MT） | メタモルフィック関係をテスト条件とするテスト技法。ソーステストケースとフォローアップテストケースの結果が関係を満たすかで合否を判定する（[lesson17](/lessons/lesson17/)、[lesson05](/lessons/lesson05/)） |

### 経験ベースのテスト

| 用語 | 説明 |
|------|------|
| 経験ベースのテスト（experience-based testing） | テスト担当者の経験・知識・直感をもとに行うテストアプローチ（[lesson18](/lessons/lesson18/)） |
| セッションベースドテスト（session-based testing） | テスト活動をテストセッションとして計画するテストアプローチ。各セッションのミッションはテストチャーターで示す（[lesson18](/lessons/lesson18/)） |
| テストチャーター（test charter） | テストセッションのゴールや目的を記述したドキュメント。英語版の用語集は、探索的テストのセッションを導くミッションステートメントと定義している。チャーターとも呼ぶ（[lesson18](/lessons/lesson18/)） |
| チェックリストベースドテスト（checklist-based testing） | チェックリストの項目を確認するようにテストケースを設計する、経験ベースのテスト技法（[lesson19](/lessons/lesson19/)） |
| クラウドテスト（crowd testing） | 多数のテスト担当者にテストを配分して実施するテストアプローチ。クラウドは群衆（crowd）のことで、クラウドコンピューティングとは別の言葉（[lesson20](/lessons/lesson20/)） |

## 第4章 品質特性のテスト

### 機能テスト

| 用語 | 説明 |
|------|------|
| 機能テスト（functional testing） | テスト対象の機能適合性を判定するテストタイプ（[lesson23](/lessons/lesson23/)） |
| 機能適合性（functional suitability） | コンポーネントやシステムが、特定の条件の下で使われるときに、明示的または暗黙のニーズを満たす機能を備えている度合い。機能完全性・機能正確性・機能適切性の 3 つの副特性を持つ（[lesson23](/lessons/lesson23/)） |
| 機能完全性（functional completeness） | 機能のセットが、指定されたすべてのタスクとユーザーの目的を網羅している度合い（[lesson23](/lessons/lesson23/)） |
| 機能正確性（functional correctness） | コンポーネントやシステムが、必要な精度で正しい結果を提供する度合い。有効な入力だけでなく、無効な入力に対する結果も含む（[lesson23](/lessons/lesson23/)） |
| 機能適切性（functional appropriateness） | 機能が、指定されたタスクと目的の達成を容易にする度合い（[lesson23](/lessons/lesson23/)） |

### 使用性

| 用語 | 説明 |
|------|------|
| 使用性（usability） | 明示された利用状況において、明示されたゴールを達成するために、明示された利用者がコンポーネントやシステムを利用できる度合い。シラバスはこの語を広い概念として使い、ISO/IEC 25010（2023 年版）のインタラクション容易性と、利用時の品質モデルの便益性を含める。インタラクション容易性は interaction capability の訳で、ISTQB 用語集では「インタラクション能力」と訳され、コンポーネントやシステムが所定の利用者とユーザーインターフェースを介して情報を交換し、意図したタスクを完了できる程度を指す（[lesson24](/lessons/lesson24/)） |
| ユーザーエクスペリエンス（user experience） | ソフトウェアプロダクトを使用した、または使用すると予想されるときの、ユーザーの認識と反応。使用の前・最中・後を含む。ISTQB 用語集の日本語版の表記は「ユーザエクスペリエンス」（[lesson24](/lessons/lesson24/)） |

### 柔軟性と互換性

| 用語 | 説明 |
|------|------|
| 柔軟性（flexibility） | コンポーネントやシステムが、要求・利用状況・システム環境の変化に適応できる程度。ISO/IEC 25010 の 2011 年版の移植性にあたり、副特性のうちテストアナリストは適応性とインストール性を担当する（[lesson25](/lessons/lesson25/)） |
| 適応性（adaptability） | コンポーネントやシステムが、異なる、または変化するハードウェア・ソフトウェア・その他の運用環境や使用環境に適応できる度合い（[lesson25](/lessons/lesson25/)） |
| インストール性（installability） | コンポーネントやシステムが、指定された環境に正常にインストールやアンインストールできる度合い（[lesson25](/lessons/lesson25/)） |
| 互換性（compatibility） | コンポーネントやシステムが他のコンポーネントやシステムと情報を交換できる度合い、および同じハードウェアまたはソフトウェア環境を共有しながら必要な機能を実行できる度合い。副特性は相互運用性と共存性（[lesson25](/lessons/lesson25/)） |
| 相互運用性（interoperability） | 2 つ以上のコンポーネントやシステムが情報を交換でき、交換した情報を使用できる度合い（[lesson25](/lessons/lesson25/)） |

## 第5章 ソフトウェア欠陥予防

### 欠陥予防とモデル

| 用語 | 説明 |
|------|------|
| 欠陥予防（defect prevention） | 作業成果物に欠陥が再発する可能性を減らし、後続の作業成果物へ欠陥が伝播するのを防ぐ措置（[lesson26](/lessons/lesson26/)） |
| モデルベースドテスト（model-based testing、MBT） | モデルに基づく、またはモデルを活用するテスト。MBT モデルからテストケースを生成でき、テストオラクルの形式化や仕様の欠陥の検出にも使える（[lesson27](/lessons/lesson27/)、[lesson22](/lessons/lesson22/)、[lesson05](/lessons/lesson05/)） |

### レビュー技法

| 用語 | 説明 |
|------|------|
| レビュー技法（review technique） | レビューを実施するために用いる方式。テストアナリストは個別レビューで使う（[lesson28](/lessons/lesson28/)） |
| アドホックレビュー（ad hoc reviewing） | 体系的なプロセスを持たず、非形式的に行うレビュー技法（[lesson28](/lessons/lesson28/)） |
| チェックリストベースドレビュー（checklist-based reviewing） | 質問または確認項目のリストに沿って行うレビュー技法（[lesson28](/lessons/lesson28/)） |
| シナリオベースドレビュー（scenario-based reviewing） | 作業成果物が特定のシナリオに対応できるかを判定するために、作業成果物を評価するレビュー技法（[lesson28](/lessons/lesson28/)） |
| ロールベースドレビュー（role-based reviewing） | さまざまなステークホルダーの役割の観点から作業成果物を評価するレビュー技法（[lesson28](/lessons/lesson28/)） |
| パースペクティブベースドリーディング（perspective-based reading） | ロールベースドレビューの一種で、チェックリストを使い、プロトタイプとなる成果物の作成を伴う（[lesson28](/lessons/lesson28/)） |

### テスト結果と根本原因分析

| 用語 | 説明 |
|------|------|
