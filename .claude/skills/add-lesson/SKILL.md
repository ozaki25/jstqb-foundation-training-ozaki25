# レッスン追加スキル

JSTQB 学習コンテンツ（モノレポ内の対象サイト）に新しいレッスンを追加します。
このプロジェクトはブランチ運用をせず、**main ブランチ上**で直接作業します。

## 引数

- `$ARGUMENTS` に対象サイト・レッスン番号・テーマ・シラバス該当箇所が渡されます
- 対象サイトは `sites/` 配下のディレクトリ名（`fl`、`al-ta` など）。以降の `<site>` はこの値に置き換える
- 対象サイトが引数にないときは、渡されたパス（`sites/<site>/...`）から判断する。判断できなければユーザーに確認する
- 例: `/add-lesson fl lesson17 デシジョンテーブルテスト シラバス 4.2.3`

## 前提: 対象サイトの CLAUDE.md を読む

作業の前に、次の 2 つを**最初から最後まで**読む。

- リポジトリ直下の `CLAUDE.md`（モノレポ共通の執筆スタイル・図版ルール・運用ルール）
- `sites/<site>/CLAUDE.md`（そのサイトの試験の前提・章とレッスンの対応表・用語の統一ルール・出典表示の文言）

レッスン番号の範囲、テーマ、シラバス該当箇所、使うべき訳語は、すべて `sites/<site>/CLAUDE.md` の対応表と用語ルールに従う。

## 作業手順

以下のステップを**すべて**実行してください。

### 1. 現在のブランチ・最新化を確認

```bash
git status
git pull origin main
```

main ブランチ上で作業する。draft ブランチや `sites/<site>/docs/drafts/` は使わない。

### 2. レッスン番号を確定

`sites/<site>/docs/lessons/` 配下の既存レッスンと `sites/<site>/docs/.vitepress/config.mts` のサイドバーを確認し、対象の `lessonNN`（NN はゼロ埋め2桁。範囲は `sites/<site>/CLAUDE.md` の対応表に従う）が未作成であることを確認する。

```bash
ls sites/<site>/docs/lessons/
```

サイドバーには全レッスンの章立て・仮タイトルが既に登録されている想定なので、対象の番号がどの章・どのテーマに割り当てられているかを `sites/<site>/docs/.vitepress/config.mts` と、`sites/<site>/CLAUDE.md` の対応表で確認する。両者が食い違っていたら、書き始める前にユーザーに報告する。

### 3. 必須インプット: シラバス該当箇所の確認

執筆前に**必ず**行うこと。省略しない。

- 対象レッスンが対応する **JSTQB/ISTQB シラバスの節番号・見出し**を特定し、該当箇所を通読する（一次資料は `references/`。FL は直下、それ以外は `references/<site>/`。ファイルがなければユーザーにアップロードを依頼する）
- そのシラバス範囲に出てくる**重要ワード（用語）をすべて洗い出し、レッスン内で網羅**する。取りこぼした用語がないか、シラバスの目次・索引と突き合わせる
- 執筆中に**自信のない記述（シラバスの記述と微妙に異なる、複数解釈がありうる、最新版シラバスとの差分が不明な箇所など）があれば、書き上げる前に申告**する。曖昧なまま断定的に書かない
- 用語はシラバスの訳語をそのまま使う（独自の意訳をしない）。サイト固有の用語ルールは `sites/<site>/CLAUDE.md` の「用語の統一ルール」に従う。二次情報（解説記事・検索結果の要約）は参考にとどめ、表記の最終確認は必ずシラバス本文（一次情報）で行う

### 4. 既存レッスンの確認

同じ章の前後レッスンや、関連するテーマのレッスンを読んで、重複や整合性を確認する。
用語の説明が既存レッスンと食い違わないようにする。

### 5. レッスンファイルの作成

`sites/<site>/docs/lessons/lessonNN/index.md` を作成します。

レッスンは以下の構成で、**シラバスの小カテゴリ（またはテスト技法）1つ分を過不足なく扱う分量**にしてください（目安は10〜20分程度。K3・K4の技法など内容の多いレッスンは長くなってよい。固定の「◯分」を看板にしない）。

```markdown
# lessonNN: テーマ — サブタイトル

## このレッスンで学ぶこと

- 学ぶこと1（1行・1文。「〜を理解する」「〜を説明できる」など）
- 学ぶこと2
- 学ぶこと3
（3〜5項目）

## 本文（テーマに応じた見出しで複数セクション）

（シラバスの定義・仕組み・具体例を、仕組み・背景から説明する）
（読むだけで概念が伝わるように、文脈がわかる完結した例や表を載せる）
（デシジョンテーブル・状態遷移図などシラバスに図表の慣習がある場合はその形式に厳密に従う）

## 試験のポイント

- 受験の切り口1（区別・ひっかけ・頻出・K レベル・K3 計算のいずれか）
- 受験の切り口2
- 受験の切り口3
（原則3項目・最大4。本文の要約ではなく受験に効く切り口だけ。K1 の網羅リストは「N 個を漏れなく想起」の1項目に集約）
```

用語の定義はレッスンに `## キーワード` 表として置かない。用語の初出は本文で太字にし、まとまった定義はサイトの[用語集](/glossary/)に一本化する（用語集は章別で、各語からレッスンへ逆リンクする）。

執筆方針:
- 見出しは名詞句で簡潔に。語りかけ調・詩的な語・「説明の足場」フレーズを避ける（詳細は review-lesson スキルのチェックリスト D・E を参照）
- 「このレッスンで学ぶこと」「試験のポイント」はそれぞれ **3〜5項目・各1行**に絞る。本文の説明を繰り返さない。項目が増えそうなときは、分割ではなく統合で数を減らす
- 用語・分類・図の構造はシラバスの表記に厳密準拠させる（FL の例: デシジョンテーブルは条件/アクション×ルール列、状態遷移は状態・イベント・遷移・アクション、リスクは「リスクの可能性」×「リスクの影響」など。サイトごとの決まりは `sites/<site>/CLAUDE.md` に従う）
- レッスン単体で完結させる。「前回」「lessonXX で」など他レッスンへの参照をしない

### 6. サイドバーの確認・更新

`sites/<site>/docs/.vitepress/config.mts` の `themeConfig.sidebar["/lessons/"]` を確認する。

- 対象 `lessonNN` の項目が既に該当する章にプレースホルダーとして存在する場合は、テーマ名が実際に書いた内容と一致しているか確認し、必要なら文言を修正する
- 存在しない場合（章立てを変更した、または計画外のレッスンを追加した場合）は、適切な章の `items` に追加する

```typescript
{ text: "lessonNN: テーマ名", link: "/lessons/lessonNN/" },
```

### 7. 機械チェック・ビルド確認

以下をすべて実行し、通ることを確認する。

```bash
node .claude/hooks/check-lesson-title.js sites/<site>/docs/lessons/lessonNN/index.md
node .claude/hooks/check-style.js sites/<site>/docs/lessons/lessonNN/index.md
node .claude/hooks/check-bold.js sites/<site>/docs/lessons/lessonNN/index.md
npm run docs:build -w sites/<site>
```

エラーや指摘があれば修正し、再度実行して確認する。可能であれば `review-lesson` スキルでレッスン単位のレビューも行う。

### 8. 完了報告

作成したファイル・更新したファイルの一覧と、実施したチェックの結果を報告する。
コミットするかどうかは、明示的な指示がない限りユーザーに確認する。他のサイトのディレクトリ（`sites/<site>/` 以外）と `packages/shared/` は変更しない。
